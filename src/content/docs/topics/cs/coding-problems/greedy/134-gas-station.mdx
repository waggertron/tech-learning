## Problem

You have `n` gas stations arranged in a circle. Station `i` provides `gas[i]` units. Traveling from station `i` to the next station consumes `cost[i]` units. You start with an empty tank at one station.

Return the starting index that lets you complete one clockwise circuit. Return `-1` when no start works. If a solution exists, the input guarantees that it is unique.

**Examples**

- `gas = [1,2,3,4,5]`, `cost = [3,4,5,1,2]` returns `3`. Starting at station 3 produces running tank values `3, 6, 4, 2, 0` after each drive.
- `gas = [2,3,4]`, `cost = [3,4,3]` returns `-1`. The route provides 9 units but requires 10.

**Constraints**

- $n = \text{gas.length} = \text{cost.length}$
- $1 \leq n \leq 10^5$
- $0 \leq \text{gas}[i], \text{cost}[i] \leq 10^4$
- A valid starting index is unique when it exists.

LeetCode 134, [Gas Station in Top Interview 150](https://leetcode.com/problems/gas-station/description/?envType=study-plan-v2&envId=top-interview-150), Medium.

## Approach 1: Brute force, try every start

For each starting index, simulate at most `n` drives. Stop as soon as the tank becomes negative. This follows the definition directly, but much of the same route can be scanned again for later candidates.

<Tabs>
<TabItem label="Python">
```python
def can_complete_circuit(gas, cost):
    n = len(gas)                                # L1: O(1)
    for start in range(n):                      # L2: outer loop, n starts
        tank = 0
        for i in range(n):                      # L3: inner loop, n steps per start
            idx = (start + i) % n               # L4: O(1)
            tank += gas[idx] - cost[idx]        # L5: O(1)
            if tank < 0:
                break
        else:
            return start
    return -1
```
</TabItem>

**Where the time goes, line by line**

*Variables: n = len(gas) = len(cost).*

| Line | Per-call cost | Times executed | Contribution |
| --- | --- | --- | --- |
| L2 (outer loop) | $O(1)$ | n | $O(n)$ |
| **L3-L5 (inner simulation)** | **$O(1)$** | **up to n per start** | **$O(n^2)$, dominant** |

For each candidate start, we simulate up to `n` steps. In the worst case, nearly every candidate travels nearly the entire route before failing.

**Complexity**

- **Time:** $O(n^2)$, driven by a full simulation for each candidate start.
- **Space:** $O(1)$.

## Approach 2: Greedy single pass (canonical)

Replace each station with its net contribution:

$$\text{net}[i] = \text{gas}[i] - \text{cost}[i]$$

The solution follows from two facts:

1. If the sum of all net contributions is negative, no start can create missing gas.
2. If a candidate first fails leaving station `i`, every station from that candidate through `i` is also impossible. The next candidate can jump directly to `i + 1`.

<Tabs>
<TabItem label="Python">
```python
def can_complete_circuit(gas, cost):
    if sum(gas) < sum(cost):                # L1: O(n) feasibility check
        return -1
    tank = 0                                # L2: O(1)
    start = 0                               # L3: O(1)
    for i in range(len(gas)):               # L4: single pass, n iterations
        tank += gas[i] - cost[i]            # L5: O(1)
        if tank < 0:                        # L6: O(1)
            start = i + 1
            tank = 0
    return start
```
</TabItem>
<TabItem label="TypeScript">
```typescript
function canCompleteCircuit(gas: number[], cost: number[]): number {
    const totalGas = gas.reduce((a, b) => a + b, 0);
    const totalCost = cost.reduce((a, b) => a + b, 0);
    if (totalGas < totalCost) return -1;                   // L1: O(n) feasibility check
    let tank = 0;                                          // L2: O(1)
    let start = 0;                                         // L3: O(1)
    for (let i = 0; i < gas.length; i++) {                 // L4: single pass, n iterations
        tank += gas[i] - cost[i];                          // L5: O(1)
        if (tank < 0) {                                    // L6: O(1)
            start = i + 1;
            tank = 0;
        }
    }
    return start;
}
```

            tank = 0
        }
    }
    return start
}

### One loop for both balances

The implementation above checks the totals first and then finds the start. The same greedy algorithm can combine those tasks into one loop:

```python
def can_complete_circuit(gas, cost):
    total = 0
    tank = 0
    start = 0

    for i in range(len(gas)):
        net = gas[i] - cost[i]
        total += net
        tank += net

        if tank < 0:
            start = i + 1
            tank = 0

    return start if total >= 0 else -1
```

**`tank` is the running balance from the current candidate start. `total` is the running balance across all stations scanned so far.** Reset only `tank` when a candidate fails. At the end, `total` answers whether the whole route supplies enough gas.

For the first example:

```text
Station index:   0   1   2   3   4
gas:            [1,  2,  3,  4,  5]
cost:           [3,  4,  5,  1,  2]
net:            [-2, -2, -2, 3,  3]
```

The `net` row is a teaching aid. The implementation computes one difference at a time and does not allocate another array.

| Station `i` | `net` | `total` so far | `tank` before any reset | Action | Candidate `start` afterward |
| --- | --- | --- | --- | --- | --- |
| 0 | `-2` | `-2` | `-2` | Reset tank to `0` | `1` |
| 1 | `-2` | `-4` | `-2` | Reset tank to `0` | `2` |
| 2 | `-2` | `-6` | `-2` | Reset tank to `0` | `3` |
| 3 | `3` | `-3` | `3` | Continue | `3` |
| 4 | `3` | `0` | `6` | Continue | `3` |

The final `total` is `0`, so return `3`. A negative `total` partway through the scan is not a reason to return early: later stations may supply the missing gas.

### What each part of the combined version does

| Code | Purpose |
| --- | --- |
| `net = gas[i] - cost[i]` | Combine collecting gas and paying to reach the next station. |
| `total += net` | Preserve the overall balance. Never reset this value. |
| `tank += net` | Check the current candidate through the drive leaving station `i`. |
| `if tank < 0` | Detect that this start cannot pay for that drive. |
| `start = i + 1` | Skip every candidate in the failed stretch. |
| `tank = 0` | Evaluate the next candidate as a fresh journey with an empty tank. |
| Final return | Reject a route with insufficient total gas, otherwise return the surviving candidate. |

A station with `gas[i] >= cost[i]` can pay for its first drive, but it may still fail later. That inequality is only a first-move check, not a complete solution. Equality is allowed: use `tank < 0`, not `tank <= 0`. A zero balance after a drive means the car successfully reached the next station with an empty tank. The tank has no upper capacity limit, so surplus can be carried forward without being discarded.

**Where the time goes, line by line**

*Variables: n = len(gas) = len(cost).*

| Line | Per-call cost | Times executed | Contribution |
| --- | --- | --- | --- |
| L1 (sum check) | $O(n)$ | 1 | $O(n)$ |
| **L4-L6 (single pass)** | **$O(1)$** | **n** | **$O(n)$, dominant** |

The sum check and greedy scan above are each linear. Their costs add to $O(n)$. The combined `total`/`tank` version uses one loop with constant work per station, also $O(n)$ time. Resets never move the scan backward or trigger another simulation, and all its running state uses $O(1)$ extra space.

**Complexity**

- **Time:** $O(n)$.
- **Space:** $O(1)$.

### Why failed candidates can be skipped

Consider net changes `[2, -1, -3, 4]`. Starting at station `0` gives a 2-unit cushion that a later start would lose:

```text
Candidate start 0:
  Leave station 0:  0 + 2 =  2
  Leave station 1:  2 - 1 =  1
  Leave station 2:  1 - 3 = -2  -> fails

Candidate start 1:
  Leave station 1:  0 - 1 = -1  -> fails immediately

Candidate start 2:
  Leave station 2:  0 - 3 = -3  -> fails immediately
```

Starting later inside that failed stretch removes an accumulated cushion. It does not make any of the later gas or travel costs more favorable. Since even the original start could not get past station `2`, neither later start can. Jump directly to station `3`.

The general rule requires the **first failure** from the current candidate. Suppose `start` first fails leaving station `i`. For any later candidate `k` in that stretch, the balance from `start` through station `k - 1` was nonnegative because the original candidate had survived that far.

```text
Balance from k through i
  = balance from start through i - balance from start through k - 1
  = a negative value - a nonnegative cushion
  < 0
```

So `k` must fail by station `i`, even if it fails earlier. Every candidate in `[start, i]` is eliminated at once. That proof is what makes skipping the stretch safe, rather than merely a guess that the next station looks better.

### Why the final candidate completes the circle

In the first example, starting at station `3` produces balances `3, 6, 4, 2, 0` after drives from stations `3, 4, 0, 1, 2`. The surplus collected near the end of the array pays for the early deficits after wrapping around.

More generally, imagine the cumulative balance starting at array index `0`, with an initial balance of zero before the first station. Each reset happens when that cumulative balance falls below the baseline of the current candidate. The final candidate therefore follows a lowest cumulative-balance point.

Starting from that lowest point, every later cumulative balance is at least the starting baseline, so the tank stays nonnegative through the array's end. After wrapping, the balance at any earlier point is the route's total balance plus the difference between that point's cumulative balance and the lowest baseline. Both terms are nonnegative when `total >= 0`. This proves the wraparound portion is safe too.

If total gas is insufficient, changing the start only changes the order of the same gains and costs. No start can fix the deficit. This is why the combined version resets the local tank but retains the global total for its final decision.

## How to recognize this pattern

**The signal:** The problem asks for a starting point on a circular sequence, and each position has a local gain and local cost. Converting those two arrays into `gas[i] - cost[i]` exposes a running-balance problem.

**The tempting wrong move:** Starting at the station with the most gas ignores the cost of leaving that station and the deficits ahead. In the first example, station 4 has the most gas, but station 3 is the answer.

**The elimination clue:** A failed running balance often proves that a whole prefix of candidates is impossible. When one failure rules out a contiguous range, look for a greedy jump instead of restarting a simulation from each position.

**The mental model:** Global balance proves that some solution exists. Local balance finds where that solution begins.

## Approach comparison

| Approach | Time | Space |
| --- | --- | --- |
| Try every start | $O(n^2)$ | $O(1)$ |
| **Greedy single pass** | **$O(n)$** | **$O(1)$** |

## Key takeaways

- Convert each station into one net value, `gas[i] - cost[i]`.
- Keep global feasibility separate from the local candidate balance.
- A negative local balance eliminates every candidate since the last reset.
- The circle does not require a second simulation once total balance is non-negative.
