## Problem

Given a string `s` and a dictionary of strings `wordDict`, return `true` if `s` can be segmented into a space-separated sequence of one or more dictionary words.

**Example**
- `s = "leetcode"`, `wordDict = ["leet", "code"]` → `true`
- `s = "applepenapple"`, `wordDict = ["apple", "pen"]` → `true`
- `s = "catsandog"`, `wordDict = ["cats", "dog", "sand", "and", "cat"]` → `false`

LeetCode 139 · [Link](https://leetcode.com/problems/word-break/) · *Medium*

## Approach 1: Recursive, try every prefix

<Tabs>
<TabItem label="Python">
```python
def word_break(s, word_dict):
    words = set(word_dict)                        # L1: O(D) to build set
    def f(start):
        if start == len(s):                       # L2: base case, O(1)
            return True
        for end in range(start + 1, len(s) + 1): # L3: try every prefix from start
            if s[start:end] in words and f(end):  # L4: O(end - start) slice + hash lookup
                return True
        return False
    return f(0)                                   # L5: initial call
```

**Where the time goes, line by line**

*Variables: n = len(s), W = word count, D = total dictionary characters, L = max word length.*

| Line | Per-call cost | Times executed | Contribution |
| --- | --- | --- | --- |
| L1 (build set) | $O(D)$ | 1 | $O(D)$ |
| L2 (base case) | $O(1)$ | once per call | $O(calls)$ |
| L3 (range loop) | $O(n)$ iterations | once per call | $O(n · calls)$ |
| **L4 (slice + lookup)** | **$O(n)$ upper bound** | **$O(n)$ per call, $O(2^n)$ calls** | **$O(n^2 2^n)$ coarse upper bound** |
| L5 (initial call) | $O(1)$ | 1 | $O(1)$ |

Without memoization, different segmentations can reach the same suffix and recompute it. A run of `"a"` characters ending in `"b"`, with dictionary words covering many lengths of `"a"`, forces repeated failed branches. There are at most $O(2^n)$ calls, each trying up to `n` endpoints with up to `n` characters of substring work. This gives a deliberately coarse exponential upper bound.

**Complexity**
- **Time:** $O(D + n^2 2^n)$ as a coarse upper bound including substring work. Memoization removes the repeated subproblems.
- **Space:** $O(n + W)$ for the call stack, word-set entries, and a temporary substring. Recursion passes indices rather than suffix copies.

## Approach 3: Bottom-up DP (canonical)

<Tabs>
<TabItem label="Python">
```python
def word_break(s, word_dict):
    words = set(word_dict)              # L1: O(D) to build set
    n = len(s)                          # L2: O(1)
    dp = [False] * (n + 1)             # L3: O(n) allocation
    dp[0] = True                        # L4: base case, O(1)
    for i in range(1, n + 1):          # L5: outer loop, n iterations
        for j in range(i):             # L6: inner loop, i iterations
            if dp[j] and s[j:i] in words:  # L7: O(i - j) slice + hash lookup
                dp[i] = True           # L8: O(1)
                break
    return dp[n]                        # L9: O(1)
```

### State: what does each slot mean?

**`dp[i]` means the first `i` characters can be segmented into dictionary words.** It does not mean that the entire prefix must itself be one dictionary word.

For `s = "leetcode"` and `word_dict = ["leet", "code"]`:

```text
Prefix length:  0   1   2   3    4     5      6       7        8
Prefix:         ""  l   le  lee  leet  leetc  leetco  leetcod  leetcode
dp:             T   F   F   F    T     F      F       F        T
```

There are `n + 1` slots because prefix lengths run from `0` through `n`. `dp[0] = True` is the valid empty prefix: it supplies a starting point for the first dictionary word. This is the [prefix-length DP convention](../../../coding-concepts/tabulation/#prefix-length-dp-and-the-empty-prefix).

### What each part of the code does

| Code | Meaning |
| --- | --- |
| `words = set(word_dict)` | Build a membership structure for whole dictionary words. `dict(word_dict)` would expect key-value pairs. |
| `dp = [False] * (n + 1)` | Reserve one slot for every prefix length, including zero. |
| `dp[0] = True` | Mark the empty prefix as valid so the first word can begin at index `0`. |
| `for i in range(1, n + 1)` | Choose the endpoint of the prefix being solved. |
| `for j in range(i)` | Try each starting position for its final word. |
| `dp[j]` | Check whether everything before the split is already segmentable. |
| `s[j:i] in words` | Check whether the entire final piece is one dictionary word. `s[i - 1]` alone would inspect only one character. |
| `dp[i] = True` | Record that a valid split was found. |
| `break` | Stop searching: this is a feasibility question, so one valid split is enough. |
| `return dp[n]` | Return whether the entire string can be segmented. |

### Concrete transitions: a valid prefix plus one last word

At `i = 4`, the split `j = 0` works:

```text
Already valid prefix: ""       dp[0] = True
Last word:            "leet"   s[0:4] in words
Result:                        dp[4] = True
```

At `i = 8`, the split `j = 4` works:

```text
Character index:   0 1 2 3   4 5 6 7
s:                 l e e t | c o d e |
Split position:           j=4       i=8

Already valid prefix: "leet"   dp[4] = True
Last word:            "code"   s[4:8] in words
Result:                        dp[8] = True
```

The reusable rule is **a valid earlier prefix plus one valid final piece makes a valid larger prefix**. Both checks must hold for the same split `j`. A dictionary word at the end cannot repair an invalid earlier prefix: `"xcode"` is false with `["leet", "code"]`, even though `"code"` is a word.

Python's `and` skips the substring check when `dp[j]` is false. Words remain in the set after use, so `"applepenapple"` can use `"apple"` twice. The loop considers all possible splits rather than committing to the first word that looks plausible.

**Where the time goes, line by line**

Let `n = len(s)`, `W` be the number of dictionary words, and `D` be their total character count. These Python bounds account for creating and hashing new substrings under average hash-table behavior.

| Line | Work | Cost |
| --- | --- | --- |
| L1 | Build the word set, including initial word hashing. | $O(D)$ |
| L2-L4 | Read the length, allocate the DP table, and set its base case. | $O(n)$ |
| L5-L6 | Try split positions for every endpoint. | At most `1 + 2 + ... + n` pairs, or $O(n^2)$ |
| L7 | If `dp[j]` is true, create and hash `s[j:i]`. | $O(i-j)$ per checked substring, up to $O(n)$ |
| L8 | Set a feasible state and stop its inner loop. | At most once per endpoint, $O(n)$ total |
| L9 | Read the final state. | $O(1)$ |

**Complexity:** The unrestricted version takes $O(D + n^3)$ worst-case time, not merely $O(n^2)$: counting split pairs alone omits substring creation and hashing. An early `break` can help individual inputs but does not remove that worst case. It uses $O(n + W)$ auxiliary space for the DP table, set entries referencing the existing words, and one temporary substring of up to length `n`. If dictionary character storage is counted too, the bound is $O(n + D)$.

The maximum dictionary-word length does not bound the substrings created by this code: the unrestricted loop still constructs candidates that are too long to match. The final version below avoids that wasted work.

## Final version: bound the last word's length

Keep the same state, base case, and two checks. Only the candidate split range changes. If the longest dictionary word has length `L`, a substring longer than `L` cannot match a word, so there is no reason to construct it.

```python
def word_break_bounded(s: str, word_dict: list[str]) -> bool:
    words = set(word_dict)
    max_len = max(len(word) for word in words)
    n = len(s)
    dp = [False] * (n + 1)
    dp[0] = True

    for i in range(1, n + 1):
        for j in range(max(0, i - max_len), i):
            if dp[j] and s[j:i] in words:
                dp[i] = True
                break

    return dp[n]
```

The problem guarantees a nonempty dictionary of nonempty words, so `max` has at least one value. A valid final word starts no earlier than `i - max_len`. Clamping that start to `0` avoids negative positions near the beginning of the string. Every valid segmentation considered by the original version is still reachable.

### Complexity discussion

Let `L` be the longest dictionary-word length and `K = min(n, L)`. The optimized version considers at most `K` splits per endpoint, for $O(nK)$ candidates. Each new substring has at most `K` characters, so slicing and hashing cost at most $O(K)$. Total time is **$O(D + nK^2)$**, commonly written **$O(D + nL^2)$** when `L <= n`. Computing `max_len` takes $O(W)$, absorbed by $O(D)$ because dictionary words are nonempty.

For this problem, `L <= 20`. That bounds the substring work at each endpoint, so the optimized scan is linear in `n` when treating the maximum word length as a fixed constant, plus dictionary setup. Without the length cap, the baseline has $O(n^2)$ candidate splits and up to $O(n)$ substring work per candidate, hence $O(D + n^3)$.

The optimized implementation uses **$O(n + W)$ auxiliary space**: the DP table, word-set references, and one temporary substring of up to `K` characters. Counting the input word characters as stored dictionary data gives $O(n + D)$ instead. A set lookup has average constant-time table probing, but hashing a newly created string still takes time proportional to its length.

This remains prefix DP. Word Break can depend on any valid earlier split within the word-length window, so the two-variable optimization from Climbing Stairs and House Robber cannot be copied directly.

## Summary

Python costs below include dictionary setup. `D` is total dictionary characters, `W` is word count, and `L` is maximum word length. The naive recursion row is a coarse upper bound that includes substring work.

| Approach | Time | Space |
| --- | --- | --- |
| Naive recursion | $O(D + n^2 2^n)$ coarse upper bound | $O(n + W)$ |
| Top-down memo | $O(D + n^3)$ upper bound | $O(n + W)$ |
| Bottom-up DP | $O(D + n^3)$ | $O(n + W)$ |
| **Length-bounded bottom-up DP** | **$O(D + nK^2)$**, `K = min(n, L)` | **$O(n + W)$** |
